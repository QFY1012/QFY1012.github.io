## 候选 c2(基于 g1,需求 judge阶段)  结果:采用,成为 g2

改动:规则 G1
  原文:- **G1 问题清单带建议列、与下一步同号**:`issues` 在「明细」一节用一张 `DataTable`(同一节还有别的明细表时排在最后),一行一条问题,列依次为编号 `id`、问题 `title`、类型 `type`、位置 `location`、影响 `affects`、严重度 `severity`、建议 `suggestion`,依次取 `span` 1、2、1、1、1、1、2;`affects` 用顿号连接色觉类型,空数组留空;`severity` 为「高」的单元格用该列 `tone` 标红;行按 `severity` 高→中→低排,同档按 `id` 排。「下一步」一节的 `List` 每条 `title` 以对应问题编号开头(如「P1 折线图系列 2、3 红绿色盲分不清」),与问题清单的编号列一一对应;`severity` 为「高」的每条都必须在「下一步」出现,不足 3 条时按严重度往下补足,多于 3 条不删;`issues` 为空时这两处都跳过。
  改为:- **G1 问题清单、修复动作与下一步同号**:`issues` 在「明细」一节用一张 `DataTable`(同一节还有 `contrast`、`confusions` 等明细表时排在它们之后),一行一条问题,列依次为编号 `id`、严重度 `severity`、问题 `title`、建议 `suggestion`、类型 `type`、位置 `location`、影响 `affects`,依次取 `span` 1、1、2、2、1、1、1,表头分别写「编号」「严重度」「问题」「建议」「类型」「位置」「影响(红/绿/蓝)」;`affects` 只写色觉类型的单字、用顿号连接(红色盲写「红」、绿色盲写「绿」、蓝色盲写「蓝」),空数组留空;`severity` 为「高」的单元格用该列 `tone` 标红;行按 `severity` 高→中→低排,同档按 `id` 排。`fixes` 紧接 `issues` 表之后用另一张 `DataTable`,一行一条修复动作,列依次为问题编号、位置 `where`、原值 `from`、新值 `to`、改前对比度 `before`、改后对比度 `after`、背景 `bg`,依次取 `span` 1、2、1、1、1、1、2;问题编号取该行 `where` 与某条 `issues` 的 `location`、`title`、`suggestion` 任一处含相同文字时那条的 `id`,匹配不到写「—」;`before`、`after` 两列都写数值,不留空;数据里没有 `fixes` 时这张表跳过。「下一步」一节的 `List` 不写 `numbered`、不写 `ordered`,把 `issues` 的每一条按同一顺序各写一条,不截断、不筛选;每条 `title` 以该条 `id` 开头(如「P1 折线图系列 2、3 红绿色盲分不清」),`description` 写该条 `suggestion`,`meta` 写该条在 `fixes` 表匹配到的改前改后数值(如「#8C8C8C → #6B6B6B,3.36 → 5.33」),匹配不到就不写;条目多于 3 条时 `List` 不写 `columns`;`issues` 为空时「下一步」和这两张表都跳过。
依据:P-05、P-06。P-05、P-06 各涉及 3 页,是剩余问题里页数最多的两条;c1 的改法方向对但把「下一步」截断成 3 条、问题表中间列折行、修复表没有编号和改前改后数值。这次在 c1 基础上补足:问题表把建议挪到问题旁、影响缩写并放末尾,修复表带问题编号和改前改后数值并紧贴问题表,「下一步」列全部问题且不再叠一套序号。
