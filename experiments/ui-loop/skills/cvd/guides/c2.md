# 输出指南 · 色觉无障碍分析 c2(候选,基于 g0)

这份指南只管「色觉无障碍分析」这个 Skill 的输出:它的数据怎么用组件库呈现、页面怎么组装。通用做法在公共规范 design.md 里,这里不重复。和公共规范 B、C 部分冲突时,以本指南为准;A 部分(基础)不能改。

## 规则

- **G1 问题清单与整改对照**: 「问题清单」一节用 `DataTable` 排 `issues`,一行一条问题,列依次为编号(`id`,span 1)、问题(`title`,span 2)、位置(`location`,span 1)、类型(`type`,span 1)、严重度(`severity`,span 1,`tone: ["高"]`)、影响(`affects`,span 1,值用「、」连接,空数组写「—」)、建议(`suggestion`,span 2),各列 span 之和为 9;行按严重度「高 → 中 → 低」排,同级保持 `issues` 原顺序,编号列照写数据里的 `id` 不重编,「问题」列照写 `title` 不省略,条数不限。`fixes` 非空时,紧接其后的「下一步」节用 `DataTable` 排 `fixes`,列依次为问题编号(span 1)、位置(`where`,span 2)、背景(`bg`,span 2)、调整前(把 `from` 和 `before` 写成「#8C8C8C 3.36」,span 2)、调整后(把 `to` 和 `after` 写成「#6B6B6B 5.33」,span 2);问题编号列写 `issues` 里 `title` 或 `location` 含该行 `where` 的那条 `id`,一条问题对应多行时逐行重复写同一个 `id`,对不上写「—」;「下一步」节必须紧跟在「问题清单」节之后,中间不插别的节,节里不再放复述 `suggestion` 的 `List`。`issues` 为空时「问题清单」节整节跳过;`fixes` 为空或没有这个字段时「下一步」节整节跳过。
