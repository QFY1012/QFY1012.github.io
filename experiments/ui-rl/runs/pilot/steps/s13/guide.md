# 输出指南 · 交互流程挖掘 g0

这份指南只管「交互流程挖掘」这个 Skill 的输出:它的数据怎么用组件库呈现、页面怎么组装。通用做法在公共规范 design.md 里,这里不重复。和公共规范 B、C 部分冲突时,以本指南为准;A 部分(基础)不能改。

## 规则

(暂无)

## 经验

写页面前先读这些经验;和上面的规则冲突时,以经验为准。

- [E1] 核心指标四项一行排满、副行同有同无，结论数字首位放大、强调唯一，背景口径后置
- [E2] 下一步建议用单列纵向编号排，依据内联在每条建议内，避免多列掉行
- [E3] 问题表把产品与步骤分列，不要合并成一格「位置」
- [E4] 不要对同一组数字用 KPI、大数字卡、横条图重复表达，同一强调层级只用一次
- [E5] 问题表保留唯一编号列，下一步建议的依据写编号对回具体条目
- [E6] 当步骤有备注时，备注在链路卡内独起一行加标签，与步骤说明分两级间距
- [E7] 任务、范围、日期等元信息只在页尾背景信息出现一次，不混入页头、结论或对比表
- [E8] 有阶段对比或产品数为 2 时，链路前用对比表并排各产品步骤数、输入项与结论
- [E9] 产品对照表独立成节并加标题，不与 KPI 或成组截图同节同屏
