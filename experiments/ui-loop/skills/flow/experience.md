# 问题清单 · 交互流程挖掘

Maintainer 从训练样本的检测结果归纳,每步更新(最近一次:flow-c2,需求 judge)。Reviser 读「布局问题」和「试过的改法」,组件 Agent 读「组件不够」。

## 组件不够

- **P-08**(需求 judge,3 页):问题清单和下一步建议要展示每条问题、建议对应的界面截图，但组件库缺少能在表格行或列表项里嵌入图片或跳转的组件，所以无法展示。
  - 证据:f2:从某条问题或建议找到对应截图时没有图号或可点击定位，只能靠「第 X 步」滚回很长的链路明细再逐张比对，页面长、来回滚动距离大;f3:问题清单和下一步到对应界面截图仍只有文字编号和界面名，没有缩略图或锚点，读者看完问题后还要滚到链路明细再找图;f4:只有文字指向，没有缩略图或跳转，读者要向上滚动很长一段，再在一堆截图里按图注逐张查找

## 布局问题

- **P-03**(需求 judge,4 页):链路明细按产品上下分成几块铺开，不同产品的同一步骤不在同一水平线上，读者无法并排对照各产品在同一环节的做法，只能来回滚动查找。
  - 证据:f1:三款银行仍按产品上下分块排列，同一环节不在同一水平线上，读者只能上下滚动来回比对，相关截图也分散在各块中;f2:快送 5 张、小橙 4 张按产品上下分成两块，同一步骤不落在同一水平线上，快送还被折成两行，读者只能上下滚动并靠记忆比对;f4:协作宝和链工上下分成两块，同一环节不在同一水平线上，读者要上下滚动并在两块之间来回对照对齐
- **P-07**(需求 judge,1 页):问题清单里每条问题的证据没有独立成列，而是并进表格下方的一段连续文字或问题单元格里，读者无法把证据与对应的问题行一一对读。
  - 证据:f1:五条证据被压成表下一段连续文字，读者核对某条问题时要在段落里按 P 编号逐句找，比看同行右侧的一列多一次来回对照;f1:两种顺序都指出当前版把证据合并到表下，问题行与证据不能同行对读，是这一版在问题清单上唯一输掉的地方

## 已解决

- **P-01**(需求 judge):链路明细里每个产品只展示开头几步的截图，后面的步骤没有图，读者无法在页面上核对问题清单和结论提到的那些界面。
- **P-02**(需求 judge):问题清单、改进建议和链路明细之间没有互相引用的定位信息（问题编号、步骤号、屏名），读者要在几节之间来回数步骤、对编号才能把问题、建议和对应界面一一对上。
- **P-04**(需求 judge):问题清单和下一步建议与链路明细之间只有编号和文字，没有指向具体截图的定位，读者要在几节之间长距离滚动、逐张数步骤才能找到对应界面。
- **P-05**(需求 judge):各产品按环节横向对比的表只有文字结论，没有步骤号或屏名指向链路明细，读者要跨产品数步骤才能把环节描述与对应界面截图对上。
- **P-06**(需求 judge):链路明细里一个产品的步骤超过一行就折到下一行，第二行没有产品名、步骤列也不与上一行对齐，读者顺着一个产品看或横向比较时要在两行之间换行并回看标题。

## 试过的改法

每个候选改了一条规则后,训练页上的效果;没采用的也留着,下次改规则先看这里。

- **c1**(需求 judge,规则 G1,采用):把链路明细从单行横向滚动改成每行最多 3 步的分行续排、保证每步都出图，并在图注末尾追加命中该步的问题编号。依据 P-01、P-02。
  - 解决了:P-01、P-02;没解决:P-03
  - 带出的新问题:每行最多 3 步的分行续排（chunkSteps / STEPS_PER_ROW=3）把超过 3 步的产品折到第二行，第二行没有产品标题、步骤列与上一行不对齐，同一产品的步骤不在一条线上，长链路要换行回扫，跨产品同一步骤也纵向错开（f1/f2/f3 都提到）。;图注在屏名后只追加了问题编号（FigureLabel 拼 issueIds），没带严重度和一句话问题描述，读者看到「第 2 步 · 会议室列表 · P2」仍要滚回问题表才知道是什么问题（f3/f4）。
  - 经验:方向对：分行续排 + 图注带问题编号让 P-01、P-02 在四个页面基本都判为解决，应保留；下次在这版上补两点——折行后给第二行补产品名/版本或让每行步骤列对齐（固定列宽），并在图注编号后补严重度或问题短描述。P-03 仍未解决，因为它依旧按产品纵向堆叠，需要另设按环节横向对齐的对照，或在问题行、建议行加可跳转锚点，减少长距离滚动找图。
- **c2**(需求 judge,规则 G2,采用):给问题清单新增「产品 · 第 N 步 · 屏名」的位置列、把下一步的「依据」展开成同样的定位写法，并把问题清单挪到链路明细之后、下一步之前。依据 P-04、P-03。
  - 解决了:P-04;没解决:P-03
  - 带出的新问题:为腾出位置列把「证据」列删掉，各页把证据并进「问题」单元格（f2/f3/f4）或压成表下一段 caption 文字（f1），问题行变长、行高不齐，读者无法与问题行同行对读证据；f4 还把建议依据从独立 meta 挪进正文，依据变成夹在建议里的一长串文字，要拆开再跨区块找。
  - 经验:方向对：加「产品 · 第 N 步 · 屏名」的定位写法确实有效，P-04 在四页都从「没解决」变为「部分解决」（f1 达到解决），但只做了一半——仍是纯文字、没有缩略图或跳转锚点，跨页滚动照旧，而 P-03（链路明细按产品上下分块、同一步骤不在同一水平线）完全没被触及。下次保留位置列与依据定位写法，但别再拿证据列和依据 meta 行做代价（证据留在独立列或做成行内小字/可展开），并把重点转到 P-03：让链路明细按步骤对齐，或在问题/建议处加可点击锚点直接跳到对应截图。
