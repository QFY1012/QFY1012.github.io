# ui-rl:输出层强化学习环境(重建计划)

ui-loop 的问题和改法见对话总结,这里只写怎么做。目标:**先得到一个在 loop 实际判断上准、稳的 reward,再用 Training-Free GRPO 的方式学习**。

新代码和新数据都放在这个文件夹;ui-loop 原样保留,作对照和复用。全部是 mock 数据,密钥只走环境变量。

| 复用(直接 import 或调用,不复制) | 来源 |

## 2. 第 0 阶段:测基线(先做,不跑 loop)

| 步骤 | 做什么 | 产物 |
|---|---|---|
| 0.1 logprobs 探针 | 对 openone 的 `deepseek-v4.1-flash` 发一次带图的请求:思考模式 high,`logprobs: true, top_logprobs: 20`,要求最后输出一个 1–9 的数字;流式和非流式都试。再试官方 DeepSeek 端点。拿不到就记下来,R2 改用采样近似 | `runs/probe/` + README 里一句结论 |
| 0.2 抽页面对 | 真实 12 个候选(flow c1–c12)× 6 份样本,每对是「候选页 vs 它的基线页」,共 72 对;另加 A/A 对测 judge 噪声:ui-loop 每次换版本都按同一指南再生成一遍训练页(`traces/*-twin`),twin 页 vs 对应的当前页,取 12 对。cvd 的候选以后可以照样加 | `labels/pairs.json` |
| 0.3 盲标 | `label.html`:左右随机交换,只给页面不给版本名;选 A 明显好 / A 稍好 / 差不多 / B 稍好 / B 明显好,可写一句理由;结果存本地并能导出 JSON。一周后随机重标 20 对 | `labels/human.json` |
| 0.4 现在的 judge 重复判 | rubric31 原判法,每对两种顺序 × 5 遍 | `runs/baseline-judge/` |
| 0.5 打分 | `eval-reward.mjs`:一致率(判出的对里和人工一致)、覆盖率(判出的比例)、复测一致(同一对多次判定一致)、A/A 对上的误判率;人工自己前后一致率 | `runs/baseline-judge/report.md` |

**这一阶段回答一个问题:现在的 judge 在 loop 的实际判断上到底准不准、稳不稳。** 人工前后一致率是 reward 能达到的上限。

## 3. 第 1 阶段:新 reward

三层,按顺序判,前一层不过就不往下走。

### 3.1 第 1 层:硬约束

直接用 `shoot.mjs` 的程序检查。有任何问题的页面在组内排最后,不参加比较。

### 3.2 第 2 层:量化指标(`lib/metrics.mjs`)

在渲染时从 DOM 量,每页输出一组数。先做这几项,每项都要在标注集上看和人工判断的方向是否一致,不一致的去掉:

| 指标 | 对应 rubric | 量法 |
|---|---|---|
| 节间距 / 节内间距 | 2 分组和韵律 | 相邻 section 的间距中位数 ÷ section 内相邻块间距中位数,≥ 2 为好 |
| 间距落在刻度上的比例 | 1、7 | 所有块间距落在 design.md 刻度(4 的倍数等)上的比例 |
| 左边线数 | 7 网格对齐 | 内容块左边缘 x 坐标聚类后的簇数,越少越整齐 |
| 字号级数 | 4 字体层级 | 页面上出现的不同字号数 |
| 强调色种数 | 5 色彩统一 | 非灰色文字和填充色的种数 |
| 同类组件高度差 | 6 同类一致 | 同一行同类组件高度的极差 |
| 最空一屏的留白比例 | 1 留白 | 每 900px 一屏,内容面积占比的最小值 |

用法:作为组内排序的一个约束。指标明显更差(超过阈值)的页面,不能排在明显更好的页面前面;差别在阈值内的交给第 3 层。

### 3.3 第 3 层:有刻度的两两比较(`lib/judge.mjs`)

- 输入:同一份数据的两页。整页缩略图 + **按节裁出的对照图**:同名的节左右并排,两页都有的节才比;只出现在一页的节单独列出。
- 输出:7 条标准各给一个 1–9 的数(1 = A 明显更好,5 = 差不多,9 = B 明显更好),最后一个总体数。要求每个数单独占一个 token。
- 期望:读每个数字位置的 top_logprobs,只留 1–9,归一化后求期望 E,p = (E − 1) / 8 是「B 更好」的概率。
- 两种顺序:p = (p(A,B) + 1 − p(B,A)) / 2。
- 汇总:7 条的 p 和总体 p 都存;排序先用总体 p,7 条用于提炼经验和分析。
- 拿不到 logprobs 时:同一请求采样 k = 5 次,用 1–9 的频率当分布。
- 模型:先用 `deepseek-v4.1-flash`;第 1 阶段末再用同一标注集试一个不同家族的多模态模型(需要另一个 key),准的那个留下。

### 3.4 验收

在第 0 阶段的标注集上跑 `eval-reward.mjs`,和基线并排比:

- 判出的对里和人工一致 ≥ 85%
- 覆盖率 ≥ 60%(|p − 0.5| 超过阈值才算判出,阈值在标注集上选)
- 同一对重复判,判出方向一致 ≥ 90%
- A/A 对上判出的比例 ≤ 10%
- 画校准曲线:p 分 5 档,每档里人工认为 B 更好的比例

**达不到就停在这里改 reward,不进第 2 阶段。**

## 4. 第 2 阶段:数据

`data/gen-data.mjs`:

- 每个 Skill 扩到 24 份:原有 6 份 + 新生成 18 份。
- 生成方式:把 `make_data.py` 的结构写成 JSON schema;LLM 按 schema 写新样本,题材、产品数、步骤数、问题数、文字长短都要有差异(特别要有内容很少和很多的样本)。
- 程序校验:字段齐全、编号连续、KPI 和明细对得上;cvd 的对比度和色差照旧由程序算,不让模型写。
- 图:沿用 `make_images.mjs`、`simulate_cvd.py`,改成接受样本列表。
- 划分:train 12 / val 6 / test 6。test 只在最后用一次。
- 人工抽查 5 份,看数据像不像真的报告。

## 5. 第 3 阶段:Training-Free GRPO 训练

### 5.1 一个 epoch(`scripts/train.mjs`)

1. **分组生成**(`rollout.mjs`):每份训练样本,用「design.md + 输出指南 + 经验库」**从零**生成 G = 4 页;生成温度调高(0.8 起,看多样性再调)。每页存 Page.tsx、截图、程序检查、量化指标。
2. **组内排序**(`rank.mjs`):三层 reward;第 3 层 4 页两两比较(6 对 × 2 种顺序);Bradley-Terry 得到组内分数。组内最高和最低的 BT 分差小于阈值时,这组跳过。
3. **轨迹**(`lib/trajectory.mjs`):从 Page.tsx 用程序提取每页的版式决定:节的顺序;每节用了哪些组件;Grid 列数和 span;数据字段放在哪一节、用什么组件;备注、截图、表格的写法。输出成一张对照表。
4. **提炼经验**(`distill.mjs`):给模型「组内最好和最差的页面 + 两页的版式决定对照表 + 7 条标准各自的 p + 当前经验库」,让它写出:哪些决定让最好那页更好;现有经验哪条缺了、错了。每条经验必须写成「当〈数据条件〉时,〈做法 X〉比〈做法 Y〉好,因为〈标准〉」。
5. **批量更新**(`update.mjs`):这个 epoch 所有组的经验汇总后,一次更新经验库。操作:新增、修改、合并、删除;每条不超过 40 字;一次最多 6 个操作;经验库总共不超过 30 条。经验库和输出指南分开存(`runs/<run>/library/e<N>.json`)。
6. **分诊**:提炼时判断成「改排版做不到」的(组件缺失、内容体量),不进经验库,记进 `runs/<run>/triage.md`,交给组件 Reviser 或人工。

### 5.2 epoch 末把关(`gate.mjs`)

- 验证样本(6 份),新库和旧库各生成 2 页,交叉两两比较(每份 4 对 × 2 种顺序)。
- 每份样本得到一个 p(新库更好的概率),6 份做 bootstrap,置信区间下限 > 0.5 才采纳新库,否则回滚到旧库,下一个 epoch 从旧库继续。
- 同时导出一组盲标页面对(验证样本上「当前库 vs g0」各 1 对),人工标完才进下一个 epoch。

### 5.3 规模

- 先做试点:flow,train 8 / val 4,G = 4,1 个 epoch。人工盲排「g0 + 经验库」vs g0。
- 试点看得出提升,再跑全量:flow 和 cvd 各 12 / 6,3 个 epoch。
- 每个 epoch 约 48 次生成 + 约 150 次判定(train 12 × 6 对 × 2 顺序 = 144,加把关 48),G = 4 时。

## 6. 第 4 阶段:监控和最终评测

- 每个 epoch 末记录两条曲线:judge 认为的「当前库 vs g0」胜率、人工盲标的胜率。两条分开就停,先查 judge。
- 最终评测:test 6 份,最终库和 g0 各生成 2 页,人工盲排。指标是人工胜率和置信区间。
- 和 ui-loop 的最终版也比一次,作对照。

## 8. 待定

- 第 3 层要不要换不同家族的模型:看 0.1 探针和第 1 阶段对比结果,需要另一个 API key。
- 输出指南(guides/g0.md)和经验库的关系:试点先「指南不动 + 经验库」;如果经验库里出现稳定的硬规则,再考虑并入指南。
- 生成模型的上限:试点看不出提升时,先换一个更强的生成模型做一次对照,判断是模型能力问题还是方法问题。
