字号、颜色、间距、表格线都由组件给出，页面只决定「用哪个组件、放在哪」。所以问题能分成两类：组件本身的毛病交给组件 Agent，排法的问题交给 Reviser 改输出指南。

2 · 组件 Agent 的迭代

Maintainer 把「组件不够」的问题交给组件 Agent。它在单独的工作区里修现有组件或新增组件，做一张示例页，由人审批：通过、写意见让它再改一版，或不采用。采用后，两个 Skill 当前版的页面都按新组件重新生成。以下全部是真实记录。

k1 · 截图组件

采用4 版 · 3 次审批意见 · 需求 2 条
  • 交互流程挖掘（程序检查）：链路明细要展示每一步的界面截图，但组件库缺少能放图片的组件，页面只能自己画 <img>。
  • 色觉无障碍分析（程序检查）：模拟视图要展示原界面和三种色觉模拟的截图，组件库同样缺图片组件。
第 1 版 · 截图按网格换行
审批意见截图部件改成横向滚动：一组截图排成一行横向滚动，更省空间；超出宽度的部分隐藏，不把页面撑宽。图按同一高度、原比例显示，不裁剪。
第 2 版 · 横向滚动
审批意见太挤了，而且滑条也不对。这种滑条也应该用 shadcn 的滑条。
第 3 版 · shadcn 滚动条
审批意见还需要更宽的间距。
第 4 版 · 图间距 48px，采用

k2

未采用需求 6 条 · 没做完就停了

组件 Agent 对「组件样式有毛病」的问题，新造了一套平行的组件，没有去修现有组件。停掉后改了 Maintainer 的写法：组件问题分成「组件库里没有」和「现有组件的样式有毛病」两种，后一种明确写出是哪个组件的哪个样式，组件 Agent 就知道该修还是该加。

k3 · 修 4 个现有组件，新增 2 个

采用1 版 · 需求 6 条（两个 Skill）
  • DataTable 的表注固定居中，口径说明脱离表格左边线（交互流程挖掘 P-03、色觉 P-09）→ 表注左对齐
  • 链路明细的两组截图之间缺分组标记（交互流程挖掘 P-10）→ 新增 Rule
  • ProgressList 是黑色粗条，比页面其他元素重（色觉 P-06）→ Progress 改成 1px 细线
  • FigureStrip 的滚动条一直显示，截图下多一条灰横条（色觉 P-10）→ 只在悬停时出现
  • FigureImage 固定高度，四张对照图太窄（色觉 P-12）→ 新增 FigureGrid，两列铺满
