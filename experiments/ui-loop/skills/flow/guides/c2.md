# 输出指南 · 交互流程挖掘 c2(候选,基于 g1)

这份指南只管「交互流程挖掘」这个 Skill 的输出:它的数据怎么用组件库呈现、页面怎么组装。通用做法在公共规范 design.md 里,这里不重复。和公共规范 B、C 部分冲突时,以本指南为准;A 部分(基础)不能改。

## 规则

- **G1 问题与链路互引**: 问题明细与链路明细用同一套「位置」写法互相指向。「链路明细」一节按 `chains` 每个产品一个 `Group`,`title` 写 `{product} · {version} · {verdict}`(chains 的 product、version、verdict);组内先放一行 `Text`,把该产品命中 `issues` 的步骤全部列出,每条写 `{id} 第 {no} 步 · {screen}`,按严重度(高→中→低)、同一严重度按 `no` 升序排,多条用「、」连接,没有命中问题的产品不放这一行;再放一个 `FigureStrip`,里面的 `Figure` 按 `steps` 的 `no` 升序排开,`FigureLabel` 写 `第 {no} 步 · {screen}`;该步命中 `issues` 里 `product` 等于该产品名、`step` 等于 `no` 的条目时,`FigureLabel` 末尾接 ` · {id}`。「问题明细」一节的 `DataTable` 第一列 `位置` 写 `{id} · {product} 第 {step} 步 · {screen}`(id 为该 `issues` 条目的 id),其中 `screen` 取 `chains` 里同名产品中 `no` 等于 `step` 的步骤的 `screen`;`issues.product` 在 `chains` 里找不到同名产品(如「全部」)时,位置写 `{id} · {product} 第 {step} 步`。表格一行一个 `issues` 条目,先按严重度(高→中→低)排,同一严重度内按该条目的产品在 `chains` 中的先后排、同产品内按 `step` 升序,找不到对应产品的条目排在同一严重度的最后。
