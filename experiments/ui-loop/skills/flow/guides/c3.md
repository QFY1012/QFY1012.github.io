# 输出指南 · 交互流程挖掘 c3(候选,基于 g0)

这份指南只管「交互流程挖掘」这个 Skill 的输出:它的数据怎么用组件库呈现、页面怎么组装。通用做法在公共规范 design.md 里,这里不重复。和公共规范 B、C 部分冲突时,以本指南为准;A 部分(基础)不能改。

## 规则

- **G1 改进建议**: 建议一节用 `List`,`columns={1}`(每条一行),不写 `numbered`、`ordered`;`items` 按 `suggestions` 数组顺序排列,条数多少做法不变。每条的 `title` 写 `${id} ${title}`(如「A1 人脸核验放到最前」),让建议编号直接出现在页面上;`description` 先写 `detail`,再写「依据:」和展开后的 `basis`——`basis` 每一项按下面三种情况展开,展开结果之间用「;」连:(1)能拆成「产品 + 第 N 步」的(含「第 1、2 步」这类多个步骤号),到 `chains` 里找 `product` 相同的那条链路、按 `no` 取对应步骤,写成「${product} 第 ${no} 步 · ${screen}」,多个步骤号逐个展开;(2)能在 `issues` 的 `id` 里找到的,写成「${id} ${title}」;(3)两者都不是的原样照写。展开后每条建议的依据不必翻到步骤明细或问题清单就能读懂。
