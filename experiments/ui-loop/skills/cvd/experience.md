# 问题清单 · 色觉无障碍分析

Maintainer 从训练样本的检测结果归纳,每步更新(最近一次:cvd-g0-k1,需求 judge)。Reviser 读「布局问题」和「试过的改法」,组件 Agent 读「组件不够」。

## 组件不够

- **P-02**(需求 judge,4 页):报告里的配色、对比度、混淆色、修复建议等表格都要展示颜色本身,但组件库缺少能显示色块(颜色样本)的组件,所以无法展示
  - 证据:c1:配色表、混淆表、对比度表、修复建议表的色值都只有十六进制文字,没有色块;修复建议表只给 #6B6B6B 这类字符串,读者看不到建议色是什么颜色;c2:配色表和混淆色表的配色列只写色值文本,这一节恰恰是讲哪两种颜色难区分却看不到颜色;c3:路况配色清单、色差表、明细表只列名称或色码文本,同一组颜色以三种形式出现却都没有色块;c4:色板表 14 行只有 token 名、色值、用途三列文字,要看到颜色必须跳到模拟视图
- **P-03**(需求 judge,4 页):模拟视图一节要把原界面和三种色觉模拟的截图并排展示供读者对照,但组件库缺少能让多张不同比例截图以可读尺寸同屏并排的组件,所以无法展示
  - 证据:c1:四张图排成一行总宽超出页面,红色盲图右半被裁掉;另一轮只出现原界面和红色盲两张,绿色盲、蓝色盲没有出现,节说明却写着三种色盲模拟;c2:四张图并排但每张都被压成缩略图,配送进度条只有几个像素宽,红绿变化根本看不出来,也没有放大或裁切图;c3:四张图横排且被裁切、不能放大,图例、系列名读不出来;c4:四个视图排成一行需要横向滚动,同屏只能看到两个,三种色盲无法并排比较
- **P-14**(需求 judge,4 页):模拟视图一节要在截图上标出问题所在的位置和图中元素的名称(图例),但组件库缺少能在截图上做标记或叠加图例的组件,所以无法展示
  - 证据:c1:图上没有系列编号或直接标注,读者无法把图中的某条线定位到下文所说的「系列 2 / 系列 3」;c2:图里没有标出或圈出问题区域,读者只能在整屏缩略图里自己找那条进度条,四张图还要各找一遍;c3:四张模拟图上没有任何图例或标注说明哪条线代表畅通、哪条代表拥堵,结论里说的混淆现象在图上无法自己验证;c4:模拟图上没有任何标记指出问题色块的位置,模拟色板里的 token 名和色值都是小字,要和色板表对应只能靠肉眼对位置

## 布局问题

- **P-04**(需求 judge,3 页):模拟视图一节里视图名与截图之间隔着大段空白,读者要靠猜才能把图和视图名对上
  - 证据:c1:两张图并排放在上方,「原界面」「红色盲」两个说明放在图下方较远的位置,读者要来回上下找才能确定哪张图对应哪个视图;c2:视图名放在图片下方、隔着一大段空白,要跨过这段距离数着列数才能把标签和图片对上;c4:视图标题与图片之间隔了大段空白,容易看错哪张标题对应哪张图
- **P-05**(需求 judge,4 页):同一个颜色在不同表里分别用名称、系列编号和色值表示,又分散在不同的节,读者要跨节比对才能确定说的是哪个颜色
  - 证据:c1:配色表用「系列 N」编号,颜色混淆表却用十六进制色值指代颜色对,两节之间隔着一整屏;问题清单只给系列号,要回配色表才知道是哪个颜色;c2:色值只出现在对比度表、名称和用途只出现在配色表,两节中间隔着混淆色、模拟视图、分类型三节;c3:「底色」列只写十六进制,而色差表和问题清单用的是「畅通/拥堵」这类名称,同一份配色数据用了两套标识;c4:色板表用英文 token 名(text-3、primary),对比度表和修正表只用中文用途名(辅助文字、主按钮悬停),要来回翻页靠猜才能对上
- **P-06**(需求 judge,4 页):问题条目、对比度数据和修复建议被拆到不同的节,彼此没有共同的编号或对应标记,读者要跨节来回翻才能知道每条建议修的是哪一项、改后是否达标
  - 证据:c1:修复建议表只有「位置」没有 P1–P6 编号,问题清单的建议、对比度表的判定、修复建议表的建议色分散三处,色盲混淆类问题没有对应修复条目;c2:下一步右侧的详情块与左侧第 1 条 P1 并排,内容却属于 P2;P1、P3 没有对应详情,按行对齐会读错;c3:问题清单没有建议列,建议统一放在最下方并另起 01–04 编号,与问题清单的 P1–P4 不是同一套;c4:修正表没有编号列,无法与问题 P1–P5 一一对应;问题 P2 在修正表里完全没有对应行
- **P-07**(需求 judge,4 页):按色盲类型只给出问题数量,不指向具体的问题条目,也没有说明统计口径,读者要跳到别节逐条筛才能知道这些数量对应哪些问题
  - 证据:c1:上面表格的「受影响」列按颜色对统计,下面条形图按问题数统计,两者口径不同却放在同一节、用同样的色盲名称,读者会以为是同一份数据;c2:分类型只给 2 / 2 / 0 的数字和光条,没有列出对应的 P1、P3 编号,也没有说明统计的是什么;c3:只给出 2/2/2 的计数,不列出对应的问题编号,读者要拿到问题清单的「影响人群」列逐个回查;c4:顶部只给「红色盲 1 个 / 绿色盲 1 个 / 蓝色盲 0 个」的计数,不列出对应的色对或问题编号,而且与核心指标的「问题总数」口径不同
- **P-08**(需求 judge,2 页):问题清单没有把每条问题的影响人群和严重度整理成可筛选的字段,读者无法按人群或严重度挑出要优先处理的问题
  - 证据:c1:严重度以小字单独排在每张卡片标题上方,和标题分离;六个问题分三列摆放,阅读顺序不明确,扫一遍很难把「高」的问题挑全;c1:每张卡片把位置、类型、影响人群、建议用「·」连成一段话,想只看建议或只看影响哪些色盲必须整段读完;c2:明细表只有编号/问题/类型/位置/严重度五列,影响哪些色盲类型整页缺失,无法按人群筛选
- **P-09**(需求 judge,4 页):同一项事实在结论、核心指标和几张明细表里给出互相矛盾的数值或说法,读者不知道以哪个为准
  - 证据:c1:结论说「有 3 对系列色几乎分不出来」,核心指标写 4 对、颜色混淆表也是 4 行;问题清单 P4 标题写 1.74,对比度表和修复建议里都是 1.84;c2:混淆色表「难以区分」列只写绿色盲,明细 P1 的受影响类型却写「红色盲、绿色盲」;同一状态在配色表里是 #2BA471,在对比度表里是 #1E7D54;c3:结论说红绿色盲都把畅通和拥堵看成同一种颜色,色差表里红色盲 ΔE 25.2 并未低于阈值;色差表标「畅通与缓行」影响红色盲,问题清单 P2 却写蓝色盲;c4:结论写「18 组中 7 组不达标」,核心指标和对比度表都是 13 组;修正表「修正前 5」与对比度表的 2.52、问题 P5 的 2.6 三个数值互相矛盾
- **P-10**(需求 judge,2 页):对比度表把达标与不达标混排在一起,没有按结果或位置分组排序,读者要逐行扫到最后才能挑出不达标项
  - 证据:c1:10 行按原始顺序平铺,没有按达标/不达标分组,判定结果在最右一列,只能一行一行扫到底;c4:18 行达标与不达标交错排列,没有按结果分组或排序,也没有按文字/按钮/链接分类,必须逐行扫「结果」列;c4:灰阶文字、按钮、链接、状态文字混在一起,想按位置归类查看也无法定位
- **P-11**(需求 judge,4 页):模拟视图与用来解释它的数据表、问题清单被排在相距很远的节,读者无法边看图边核对数据,只能反复长距离滚动
  - 证据:c1:混淆表与模拟图相隔近千像素,问题清单又在页面最下方,拿着问题回图里核对要反复滚动;c2:描述进度条问题的混淆色表在模拟视图上面好几节,图和说明无法对着看;c3:图在页面中部,ΔE 数值表在下面隔着一整块配色列表,两者无法同屏;同一级路况的色值、对比度、色差、相关问题分散在四五个区块;c4:图上的 token 和色块在模拟视图,结论分散在后面几节隔了整页,判定标准又放在整页最末
- **P-12**(需求 judge,4 页):一行放不下时多出来的条目折到下一行(核心指标的数字、三列排布的列表条目),阅读顺序被打断,读者容易漏看或把条目对应错
  - 证据:c1:四个指标排成 3 个一行加 1 个另起一行,「对比度不达标 6 组」与换行后的「问题总数 6 个」数值相同又不在同一行,容易被当作重复项或漏看第四项;c2:「问题总数 3 个」单独折到第二行,和另外三项不在同一行,扫读总览时视线要跳一次;c3:四个指标排成两行,第二行只有「检查的文字与背景组合 4 组」,正好落在「问题总数 4 个」正下方,容易当成补充说明;四条修复建议排成三列,04 折到第二行第一列正好在 01 下方,按 01→04 读会先读到 04 再折回 02;c4:四个指标排成三列,第四个「问题总数 5」折到第二行且与上面三个不对齐
- **P-13**(需求 judge,2 页):颜色混淆表和对比度条只给原始数值,不标出阈值线或是否达标,读者要逐格与阈值心算比较
  - 证据:c1:判定阈值 ΔE<12 只写在节标题的副标题里,滚到表格中段已看不见;表内 4 行 × 3 种色盲共 12 个数值没有任何达标/不达标的标记,读者要逐个与 12 比较;c1:「受影响」列只给文字汇总,看不出是哪个数值触发的;c3:对比度条只给 2.22／11.25／3.55／8.36 四个比值,没有标出基准线,也没有达标与否的结论,要判断必须翻到下面明细表看「结果」列
- **P-15**(需求 judge,1 页):修复建议表把原色值、建议色值、底色并排列出,列名与内容不对应,读者看不出实际要改的是文字色还是背景色
  - 证据:c4:原色值和建议色值都写 #FFFFFF,真正的变化在「背景」列(#096DD9),列名与内容不对应,容易读成「没有修改」;c4:同一列在不同行含义不同(有的改文字色、有的改背景色),读者无法确定这一项到底要改什么;c4:这一行同时出现「修正前 5」与对比度表的 2.52,读者无法判断现状值

## 试过的改法

每个候选改了一条规则后,训练页上的效果;没采用的也留着,下次改规则先看这里。

- **c1**(需求 judge·旧标准,规则 G1,未采用:需求 judge 算数的意见在 c5、c6 上变多):把配色、混淆色、对比度、修复四张表合并成一节「色板与检查」(紧跟模拟视图、排在问题清单前),并把页面上的颜色值统一写成「名称 色值」。依据 P-05。
  - 解决了:P-05;没解决:P-02
  - 带出的新问题:四张表并成一节、caption 落在表格下方又彼此紧挨,c3/c4 新增「先看到数据才看到表名、容易把下一张表的数据串到上一张」的意见;G1 要求凡颜色值都写「名称 色值」,让 c1 配色表自己的「色值」列重复了左侧「名称」列;G1 还无条件要求「修复」表,c3 数据里没有 fixes,于是渲染出一张只有表头的空表(在 c2 也与既有「下一步」区块叫法不一致)。
  - 经验:方向对:P-05「同一颜色要在不同节之间比对」的意见在 c2/c3/c4 上消失,说明合并+统一「名称 色值」有效(c1 残留的一条已主要是无色块问题);但本次没碰 P-02,组件库仍没有色块,四张表挤在一节依然只能看文字。下次保留合并与统一命名,补三点——palette 表自身的色值列不重复写名称、「修复」表按数据有无条件渲染、表名放表格上方并给四表留分隔;更根本的是先补色块组件,否则颜色表怎么合并都读不出颜色。
- **c2**(需求 judge·旧标准,规则 G1,未采用:需求 judge 算数的意见在 c5 上变多):把配色、混淆色、对比度、色值修正四张表合并成一节「色板与检查」(紧跟模拟视图、排在问题清单前),颜色统一写成「名称 色值」、空表整块不渲染、受影响色差列标红。依据 P-05。
  - 解决了:P-05;没解决:P-06
  - 带出的新问题:混淆色表新加的标红(受影响色差列)没有就地给出判定阈值,合并后整节描述也不再写「ΔE<12」,读者看到被标红的 9.0 不知依据(c2、c3),是「色差列标红」和「四表合并共用一句节描述」这两处造成的。统一写「名称 色值」后,色值修正表里原色与修正色同为 #FFFFFF、真正改动在背景列的那一行也更容易被漏读(c4)。
  - 经验:方向对:合并四表 + 统一「名称 色值」确实消掉了跨节找颜色(P-05)的意见,条件渲染、表名与 48px 分隔应保留;但只合并表格解决不了 P-06,问题清单、对比度、色值修正之间仍需共用编号或对应标记。下次在原改法上补:标红的色差列就地写明阈值(如组标题写「ΔE<12 标红」),并把问题编号带进对比度与色值修正表;去掉只标红、不给依据的呈现。
- **c3**(需求 judge,规则 G1,未采用:需求 judge 算数的意见在 c5、c6 上变多):把配色、混淆色、对比度、色值修正四张表合并成一节「色板与检查」紧跟模拟视图,色值统一写成「名称 色值」,色差按受影响标红并把 ΔE 阈值写进组标题,对比度表与色值修正表新增与问题清单共用的问题编号列。依据 P-05、P-06。
  - 解决了:P-13;没解决:P-05、P-06、P-15
  - 带出的新问题:新加的「问题编号」列在对比度表、色值修正表里几乎整列填「—」(issueIds 只按 location 相同或互相包含匹配,实际数据对不上),读者仍无法把这两张表与问题清单对上;混淆色表的 ΔE 判定改成只对受影响数值标红、阈值只写进 Group 标题,被指出仅靠颜色区分、缺少非颜色标记(affectedTone 标红那一处造成)。
  - 经验:方向可以保留(四表合并、统一「名称 色值」、阈值进组标题),但要把编号对应做实:location 写法不一致时不能只靠相同/互相包含匹配,必须给回退规则(否则整列「—」等于白加一列,反而更对不上),色差标红也要配非颜色标记,不能只用颜色。这次合并只是把表挪到一起,没解决跨节核对、缺色块和口径矛盾(P-02/P-03 受组件限制),下次要么先补组件,要么把改动收窄到真能靠编号串起来的范围。
