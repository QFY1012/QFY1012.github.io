CHI'26  人机交互 CCF-A
2025.07 — 2025.11
背景
LLM 线性对话界面导致新手用户在多轮分析中迷失方向，难以回溯历史、对比分支路径；现有方案仅提供孤立的"下一步推荐"，缺乏对整体探索过程的全局可视化。
任务
为现有 LLM 对话界面设计一款分析树插件，将零散对话自动重组为可交互的树形结构，支持分支创建、路径回溯与全局概览，提升探索效率。
行动
① 对 205 条用户 Prompt 进行主题分析编码，归纳出 7 类查询类型 + 2 类分析机会点，为系统设计奠定实证基础； ② 基于 LangChain 搭建 对话式可视分析 对话底座：编排 LLM Workflow，用户每轮自然语言提问后生成 Vega-Lite 图表规格代码并实时渲染为可交互图表； ③ 定义分析树数据结构并设计节点生成算法：从每轮对话中提取图表所展示的数据属性与筛选条件，再调用多模态 LLM（Gemini 2.5 Flash）以 Few-shot + Multiple Choices Prompting 从图表中识别值得深挖的分析机会点，构建分析节点； ④ 设计节点插入算法：基于 7 类查询类型归纳出 7 条连接规则，自动判断新节点应连接在哪个已有节点下； ⑤ 编排推荐生成 Workflow：提取从根节点到当前节点的完整探索路径作为上下文，再结合当前节点的分析机会点，利用 Multiple Choices Prompting 预测后续 Query 的数据维度与筛选条件，并推荐后续分析节点与query。
结果
对比线性对话界面（N=12），洞察数量 ↑58.3%，深度思考时间 ↑17%；研究独立完成，录用于 CHI'26。
面向数据叙事的 Agent 交互产品设计↗ 点击查看项目详情独立完成
UIST'26 在审  人机交互 CCF-A
2026.01 — 2026.04
背景
LLM Agent 能自动完成数据报告等复杂任务，但执行过程不透明、不可控；现有方案（如 Manus）只暴露操作日志，用户看不清报告的构建逻辑。
任务
将 Agent 的探索过程从操作日志重构为叙事故事线，并可视化呈现，让用户一眼看清报告走向并随时干预。
行动
① 定义数据故事线数据结构：每个节点记录"当前分析了哪些指标、用了哪些筛选条件、发现了什么"，节点之间用 6 种叙事关系（对比、细化、因果等）串联，把 Agent 零散的操作记录变成一条有逻辑的故事线； ② 基于 LangGraph 构建 ReAct Agent，封装数据探索与洞察计算工具，Agent 通过工具调用自主探索数据，提出多个候选故事线节点； ③ 编排故事线扩展 Workflow，利用 Multiple Choices Prompting 从候选节点中，按逻辑性、连贯性、多样性、相关性四个维度评选最优节点挂入故事线，并生成图表渲染代码； ④ 设计叙事空间可视化：将故事线投影至圆盘，节点位置反映其探索的数据维度，空白区域即为未探索方向，用户可通过拖拽手势直接指定 Agent 下一步走向，无需手写 Prompt。
结果
对比树形 baseline（N=16），故事洞察数量 ↑13.2%（p=0.035），心理负荷显著下降（p=0.046），感知可控性显著提升（p<0.05）；15/16 参与者主动使用拖拽干预；投稿至 UIST'26，目前在审中。
