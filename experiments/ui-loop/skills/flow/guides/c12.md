# 输出指南 · 交互流程挖掘 c12(候选,基于 g3)

这份指南只管「交互流程挖掘」这个 Skill 的输出:它的数据怎么用组件库呈现、页面怎么组装。通用做法在公共规范 design.md 里,这里不重复。和公共规范 B、C 部分冲突时,以本指南为准;A 部分(基础)不能改。

## 规则

- **G1 核心指标一行排满**:核心指标节的 `kpis` 排成一行,行内每项等宽、整行排满,不允许出现「一行 3 个 + 第二行 1 个」的折行;个数 ≤ 4 时用 `<Grid cols={12} fields={false}>`,每项 `span={12 / 个数}`(2 个各 `span={6}`、3 个各 `span={4}`、4 个各 `span={3}`);个数为 5–6 时每行 3 个(`span={4}`),最后一行不足 3 个时把这一行的项改成 `span={12 / 该行个数}` 排满整行(5 个 = 第一行 3 个 `span={4}` + 第二行 2 个 `span={6}`)。
- **G2 链路明细:一组一栏、栏底齐平**:链路明细节里 `chains` 一个产品一组,每组一个 `Group`(`title` 写 `{product} · {version}`),组内一个 `FigureStrip`,按 `steps[]` 顺序排开,每步一个 `Figure`,顺序固定为 `FigureImage`(取 `step.image`)→ `FigureLabel`(写「第 {no} 步 · {screen}」)→ `FigureText`;所有产品组从同一条左对齐线开始、用同一个图高,列宽只随截图比例,不为排满而缩放,步骤多的组照常向右排;`FigureText` 一律压成一行,写「{content} · {action}」,`inputs` 大于 0 时末尾补「输入 {inputs} 项」,`note` 不写进图里,让各组截图下方的文字行数一致、栏底齐平;`Section` 加 `className="gap-12"`,产品组之间 48px,组内 24px,图与标签、说明之间 8px,组间不加分隔线。
- **G3 首屏元数据并入封面、末屏问题与建议同节**:`task`、`scope`、`date` 不再单独成节;在 `Page` 的 `meta` 里按 产品、周期、任务、范围、日期 的顺序写全,缺的项不写,页头不再出现「背景信息」节;`issues` 和 `suggestions` 都存在时,把「问题明细」和「下一步」放进同一个 `Section`——`Section` 的 `title` 写「问题建议」,加 `className="gap-12"`,内容依次是 `Group`(`title` 写「问题明细」)包住问题 `DataTable`、`Group`(`title` 写「下一步」)包住建议 `List`,两组之间 48px、组内 24px;缺其中一个时该节只放存在的那一块,`title` 相应写「问题明细」或「下一步」;其余各节顺序不变,页面由这一节收尾。
